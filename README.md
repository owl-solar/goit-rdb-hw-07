# GoIT RDB Homework 7: Time-series та напівструктуровані дані в PostgreSQL

Цей репозиторій містить рішення для сьомого домашнього завдання курсу з реляційних баз даних (PostgreSQL), присвяченого інженерії ознак для машинного навчання (`time-series ML features`), роботі з напівструктурованими даними (`JSONB`), оптимізації за допомогою індексів (`GIN`, `Expression B-tree`) та аналізу планів виконання через `EXPLAIN ANALYZE`.

---

## 📊 Джерело даних та метод отримання

Основний датасет для аналізу та побудови ML-ознак — офіційні дані про поїздки жовтих таксі в Нью-Йорку (**NYC Yellow Taxi Trip Records**), які збираються та публікуються комісією **NYC Taxi and Limousine Commission (TLC)**.

* **Формат даних:** Колонкові файли у форматі Parquet (`yellow_tripdata_2024-03.parquet`).
* **Офіційне джерело (URL):** `https://d37ci6vzurychx.cloudfront.net/trip-data/`
* **Ключові поля з сирого набору (`nyc_taxi_raw`):** `tpep_pickup_datetime`, `tpep_dropoff_datetime`, `PULocationID`, `DOLocationID`, `trip_distance`, `fare_amount`, `passenger_count`.
* **Трансформація:** Агрегація на щоденному рівні за зонами посадки (`pickup_zone_id`, `ts_day`) у таблицю `t7_hw_taxi_daily`.

> **⚠️ Статус джерела даних (Stub-schema fallback):**
> У цьому виконанні **використано stub-schema fallback** (генератор тестових даних на базі `generate_series`) у зв'язку з оптимізацією часу виконання та мережевими обмеженнями зовнішнього сховища Parquet-файлів у середовищі Google Colab. Це гарантує повну відтворюваність усіх розрахунків time-series ознак, JSONB-подій та індексів без залежності від сторонніх серверів.

---

## Структура проекту та опис завдань

1. **Завдання 1: Setup і завантаження даних**
   - Налаштування локального середовища PostgreSQL у Google Colab за допомогою бібліотеки `pgembed`.
   - Завантаження та агрегація даних у таблицю `t7_hw_taxi_daily`.

2. **Завдання 2: Time-series ML features**
   - Побудова чотирьох категорій ознак (`lag-1d`, `lag-7d`, `lag-30d`, ковзне середнє за 7 днів, волатильність за 30 днів, кумулятивні показники) з обов'язковим `PARTITION BY pickup_zone_id`.
   - Об'єднання у поданий `VIEW` (`v_t7_hw_taxi_features`).

3. **Завдання 3: JSONB-таблиця для подій**
   - Створення синтетичної таблиці `t7_hw_events` на 50 000 рядків із 5 типами подій і різною структурою `payload`.
   - Виконання запитів із операторами containment (`@>`), перевірки ключів (`?`, `?|`) та розширеного `JSONPath`.

4. **Завдання 4: GIN-index demo + EXPLAIN ANALYZE**
   - Дослідження впливу GIN-індексу типу `jsonb_path_ops` на плани виконання аналітичних запитів (`EXPLAIN (ANALYZE, BUFFERS)`).
   - Створення `Expression B-tree index` для оптимізації скалярних текстових виразів (`payload ->> 'device'`).

5. **Завдання 5: JSONB vs Normalized + Reflection**
   - Створення нормалізованої реляційної таблиці для подій `checkout` (`t7_hw_checkouts_norm`) та порівняння продуктивності запитів.
   - Детальна архітектурна рефлексія та висновки щодо вибору між документами (`JSONB`) і реляційною структурою в ML.
