# GoIT RDB Homework 7: Time-series та напівструктуровані дані в PostgreSQL

Цей репозиторій містить рішення для сьомого домашнього завдання курсу з реляційних баз даних (PostgreSQL), присвяченого інженерії ознак для машинного навчання (`time-series ML features`), роботі з напівструктурованими даними (`JSONB`), оптимізації за допомогою індексів (`GIN`, `Expression B-tree`) та аналізу планів виконання через `EXPLAIN ANALYZE`.

---

## Джерело даних

Основний датасет для аналізу та побудови ML-ознак — офіційні дані про поїздки жовтих таксі в Нью-Йорку (**NYC Yellow Taxi Trip Records**), які збираються та публікуються комісією **NYC Taxi and Limousine Commission (TLC)**.

* **Формат даних:** Колонкові файли у форматі Parquet (наприклад, дані за місяць `yellow_tripdata_2024-03.parquet`).
* **Офіційне джерело (URL):** `https://d37ci6vzurychx.cloudfront.net/trip-data/`
* **Ключові поля, що використовуються з сирого набору (`nyc_taxi_raw`):**
  * `tpep_pickup_datetime` / `tpep_dropoff_datetime` — час початку та завершення поїздки;
  * `PULocationID` / `DOLocationID` — ідентифікатори зон посадки та висадки пасажирів;
  * `trip_distance` — пройдена дистанція в милях;
  * `fare_amount` — вартість поїздки за лічильником;
  * `passenger_count` — кількість пасажирів.
* **Трансформація:** Для задач побудови часових рядів сирі рядки агрегуються на щоденному рівні за зонами посадки (`pickup_zone_id`, `ts_day`) у таблицю `t7_hw_taxi_daily` (розраховуються `trip_count`, `avg_fare`, `total_distance`).
* **Альтернатива (Stub-schema fallback):** Якщо завантаження файлу з офіційного сховища заблоковане мережею, у проєкті передбачено використання генератора тестових даних (`stub-schema`) на основі `generate_series`.

## Структура проекту та опис завдань

1. **Завдання 1: Setup і завантаження даних**
   - Налаштування локального середовища PostgreSQL у Google Colab за допомогою бібліотеки `pgembed`.
   - Завантаження, фільтрація та агрегація сирих даних NYC Yellow Taxi в таблицю `t7_hw_taxi_daily`.

2. **Завдання 2: Time-series ML features**
   - Побудова чотирьох категорій ознак для ML на рівні зон посадки з обов'язковим використанням `PARTITION BY pickup_zone_id`:
     - **Lag features:** `lag-1d`, `lag-7d`, `lag-30d`.
     - **Rolling average:** ковзне середнє значення вартості поїздки за 7 днів (`RANGE BETWEEN INTERVAL '6 days' PRECEDING AND CURRENT ROW`).
     - **Rolling volatility:** стандартне відхилення (`STDDEV_SAMP`) за 30 днів.
     - **Expanding cumulative:** накопичувальні суми та середні показники від початку ряду.
   - Об'єднання ознак у єдиний поданий `VIEW` (`v_t7_hw_taxi_features`).

3. **Завдання 3: JSONB-таблиця для подій**
   - Створення синтетичної таблиці `t7_hw_events` на 50 000 рядків із п'ятьма різними типами подій та гнучкою структурою `payload`.
   - Виконання запитів із використанням операторів containment (`@>`), перевірки наявності ключів (`?`, `?|`) та розширеного `JSONPath` (`jsonb_path_query`, `jsonb_path_exists`).

4. **Завдання 4: GIN-index demo + EXPLAIN ANALYZE**
   - Дослідження впливу GIN-індексу типу `jsonb_path_ops` на план виконання аналітичних запитів (`EXPLAIN (ANALYZE, BUFFERS)`).
   - Демонстрація обмежень GIN-індексу для скалярних текстових виразів та створення спеціального `Expression B-tree index` для поля `payload ->> 'device'`.

5. **Завдання 5: JSONB vs Normalized + Reflection**
   - Створення нормалізованої реляційної таблиці для подій `checkout` (`t7_hw_checkouts_norm`) та порівняння продуктивності запитів із JSONB-версією.
   - Детальна архітектурна рефлексія щодо вибору між документами (`JSONB`) та реляційною структурою в ML-інфраструктурі.
